# Шаблонный репозиторий проекта

## Описание

Шаблонный репозиторий проекта с поддержкой модулей Git и организацией сборки через CMake

## Структура

### Директориии

[SRC](./SRC) - директория исходных текстов проекта. Необходимо создать поддиректорию(ии) с именем библиотеки (SRC/lib1, SRC/lib2, ...)

**SRC/lib.../interface** - директория с интерфейсными заголовочными файлами. Данную директорию необходимо создать в директориях каждой библиотеки

[Tests](./Tests) - директория тестов проекта. Аналогично директории SRC необходимо создать поддиректорию для каждой библиотеки (Tests/lib1, Tests/lib2, ...)

[modules](./modules) - директория модулей (зависимостей) проекта

**modules/tlk_build** - обязательный модуль для всех проектов, определяющий основные правила сборки

### Основные файлы CMake

[CMakeLists.txt](./CMakeLists.txt) - файл, определяющий проект, путь к модулям и подключающий основные настройки сборки из tlk_build

[SRC/CMakeLists.txt](./SRC/CMakeLists.txt) - файл, определяющий правила сборки основного таргета, его настройки, зависимости, проброс интерфейса и т.п.

[Tests/CMakeLists.txt](./Tests/CMakeLists.txt) - файл, определяющий правила сборки тестов

## Правила использования

1.  Создать свой рипозиторий на основе данного шаблона средствами GitTea
2.  Создать ветку dev средствами GitTea
3.  Склонировать репозиторий в свою файловую систему: ```git clone http://git-server...```
4.  Перейти в директорию склонированного репозитория
5.  Переключиться на ветку dev
6.  Создать директорию для модулей ```mkdir modules```
7.  Подключить нужные модули, например tlk_build, находясь в корне репозитория: ```git submodule add --name tlk_build http://git-server:3000/SKPO/tlk_build.git modules/tlk_build```
8.  При необходимости переключить все модули на актуальную рабочую ветку: ```git submodule foreach 'git checkout dev'```
9.  Если нужно, переключить конкретный модуль на нужную ветку: ```cd modules/tlk_build; git checkout dev; cd -```
10. Создать поддиректории в SRC и Tests для планируемых библиотек (SRC/lib..., Tests/lib...)
11. Для проектов библиотек создать поддиректорию SRC/lib.../interface и помещать туда интерфейсные заголовочные файлы
12. Настроить файлы CMakeLists.txt под свой проект
13. При необходимости обновлять все модули до последних изменений: ```git submodule foreach 'git pull'```, либо вручную каждый модуль: ```cd modules/tlk_build; git pull; cd -```
14. Средствами GitTea создавать запросы на слияние из dev в main

## Примечание

Если склонировать репозиторий, в котором уже подключены модули, то следует их инициализировать: ```git submodule init; git submodule update```
